# Documentation Index

Use this order for current work:

1. `../CURRENT-STATE.md` — current operational source of truth.
2. `../PROJECT-HANDOFF.md` — baseline, validation, and continuation context.
3. `RESCUE-WORKFLOW.md` — how current work must be executed.
4. `UI-ROUTE-MAP.md` — canonical, merged, and quarantined UI routes.
5. `product-vision.md` — long-term product intent.
6. `architecture.md`, `roadmap.md`, `project-state.md`, and `module-*.md` — historical architecture/lifecycle evidence. These may contain old “active module” statements and do not override `CURRENT-STATE.md`.

Historical files are intentionally retained because contract tests and design decisions reference them. Do not delete or rewrite them in bulk merely to make the docs folder look smaller.
